Troubleshooting

Sign-In and Email

Verification or password-reset email does not arrive

rolv sends verification and password-reset messages from noreply@rolv.io.

  1. Wait 1–2 minutes and check your spam or junk folder.
  2. On the verification screen, click Resend verification email, open the link, then click I’ve verified.
  3. On the sign-in screen, click Forgot password? and confirm the exact registered email address.

Google sign-in does not require email verification.

Environment Setup

Mamba/Micromamba Not Found

rolv downloads Micromamba automatically to ~/.rolv/bin/micromamba (%USERPROFILE%\.rolv\bin\micromamba.exe on Windows) if no Mamba binary exists on your computer.

This error appears only if the automatic download fails (for example, no internet access or a firewall blocks micro.mamba.pm) or if a custom Mamba Path points to a missing file.

To fix this error:

  1. Open Settings → Execution Tools.
  2. Clear Mamba Path so rolv detects or downloads Micromamba automatically, or enter the full path to an existing mamba or micromamba executable (for example, /opt/homebrew/bin/micromamba).
  3. Click Save Changes.

If the automatic download still fails, install Micromamba manually:

  • macOS / Linux (Terminal):
    "${SHELL}" <(curl -L micro.mamba.pm/install.sh)
  • Windows (PowerShell):
    Invoke-Expression ((Invoke-WebRequest -Uri https://micro.mamba.pm/install.ps1).Content)

Python or R Environment Creation Fails

  • Verify internet access so Mamba can download packages on first run.
  • Select another Python or R version in Settings → Execution Tools.
  • After changing the R Version, start a new session or clear old _template_r* folders so Mamba builds a fresh template.

Cached Environment Spec Errors (_template_)

If you see libmamba Could not solve for environment specs referencing _template_:

  1. Close active runs and remove cached templates in Terminal:
    rm -rf ~/.rolv/envs/_template_*
  2. Re-run the node or workflow so rolv creates a clean environment.

Reset or Create a Fresh Environment

rolv stores Python and R runtime files in three locations under your home folder:

  • Template (~/.rolv/envs/_template_*): A reusable base environment and its .spec.txt package list. rolv builds one template for each Python or R version and copies it to make new session environments quickly.
  • Session environment (~/.rolv/envs/<hash>_python and <hash>_r): An isolated Python or R environment for one working directory. rolv installs project-specific packages into this folder.
  • Package cache (~/.rolv/mamba): Downloaded Micromamba package archives. Micromamba reuses these files to install packages faster.

Note: You can safely delete these folders. This action does not delete your working directory files, recipes, sessions, or settings (executor-config.json).

Reset templates only

Use this procedure if template creation fails or you want fresh base templates for new workspaces. This procedure does not change existing session environments.

  1. Stop all active runs in rolv.
  2. Delete the template folders and .spec.txt files:
    • macOS / Linux (Terminal):
      rm -rf ~/.rolv/envs/_template_*
    • Windows (PowerShell):
      Remove-Item -Recurse -Force "$env:USERPROFILE\.rolv\envs\_template_*"
  3. Run a script or workflow in rolv. rolv builds new templates automatically.

Reset all environments

Use this procedure if a session environment fails or you want a clean environment for every project.

  1. Stop all active runs in rolv.
  2. Delete the envs folder:
    • macOS / Linux (Terminal):
      rm -rf ~/.rolv/envs
    • Windows (PowerShell):
      Remove-Item -Recurse -Force "$env:USERPROFILE\.rolv\envs"
  3. Run your script or workflow again. rolv builds a new template and a new session environment automatically.

Clear the package cache

Use this procedure if Micromamba reports file-lock, extraction, or corrupted archive errors.

  1. Stop all active runs in rolv.
  2. Delete the envs folder and the mamba package cache:
    • macOS / Linux (Terminal):
      rm -rf ~/.rolv/envs ~/.rolv/mamba
    • Windows (PowerShell):
      Remove-Item -Recurse -Force "$env:USERPROFILE\.rolv\envs", "$env:USERPROFILE\.rolv\mamba"
  3. Run your script or workflow again. Micromamba downloads fresh packages and builds a clean environment.

Code Execution

Scripts Do Not Run

  • Ensure a working directory is selected (click the folder icon in the chat or graph header).
  • Check that Auto-Run is enabled in Chat View if you expect automatic execution.
  • Inspect the Logs tab in the Node Inspector for runtime errors.
  • Click Stop to cancel a running script.

Generate Data Fails or Leaves Inputs Empty

Open the Data Input node and expand Test data:

  • Editor is empty: Sign in, choose R, Python, or Bash, and click Starter.
  • Generation failed: Confirm the language selector matches the script language, fix errors shown in the alert, and click Generate Data again.
  • Inputs stay empty: Confirm the script finishes by writing test_input.json in the working directory with keys matching your Data Input fields.
  • Run with Test Data reports missing script: Click Starter on the Data Input node first.

Old Recipe Data Input Appears as a Compute Node

Re-open the source graph and click Save as Recipe again so Data Input and Data Output save as I/O nodes instead of compute nodes.

Use Recipe Started a Different Session

Clicking Use Recipe on a card or Run Recipe in the library always creates a new graph session. Type the recipe name or run it inside an existing chat to replace that chat's graph instead.

Missing Python or R Packages

  • rolv maps common Python imports (for example, cv2 to opencv-python, sklearn to scikit-learn) and tries pip if Conda cannot find a package.
  • Add missing packages to python-requirements.txt or r-packages.txt in the recipe's Environment tab so future runs install them automatically.

SSH Execution Fails

  1. Open Settings → Execution Tools → Remote Compute.
  2. Click Test to verify host, port, username, and key or password authentication.
  3. Confirm the remote work directory exists and your remote Python command works.

If Add Target is disabled, you reached your account's remote compute slot cap (Free: 1, Academic: 3).

Search and Embeddings

Poor Semantic Search Results

  • Open Settings → API Hub → Embedding Model and click Test Connection.
  • Save changes and allow local recipe re-indexing to finish. Re-indexing large libraries takes a few minutes.

Cloud Sync and Updates

Recipe "No Longer on Cloud"

If an author removes a cloud recipe, your local copy continues to work with a No Longer on Cloud badge, without future cloud updates.

Improvement Report Prompts

  • To hide prompts temporarily, click Snooze 14d.
  • To disable prompts permanently, click Turn off or set rolv Improvement Reports to Turn off (never ask) in Settings → Execution Tools.
  • If you dismiss the floating toast outside Chat View, the report prompt stays available in Chat View until sent, snoozed, or turned off.

Token Quotas

When you reach your daily or monthly token limit:

  • Wait for the daily reset at midnight UTC, or
  • Configure a custom LLM (OpenAI, Groq, OpenRouter, or local Ollama) in Settings → API Hub and set Usage Mode to Use as Fallback or Always Use.

Research Nodes

Research Report Cuts Off Mid-Table

Use Structured output with explicit column names so rolv writes {label}_node_output.json instead of a long prose essay.

Structured Output Summarized Only One Item

Enable Batch iteration across items (ForEach) on the research node to process rows across a table in parallel (up to 100 items).

Research Failed with fetch failed

Verify your internet connection, VPN or proxy settings, and confirm you are signed in to rolv.

Connected Node Cannot Read Upstream File

Arrows enforce execution order only. Compute node A must write a named file in the working directory, and node B must open that exact filename.

App Updates

When a new version downloads in the background, an update bar appears at the bottom of the window:

  • macOS (unsigned builds): Click Show in Finder to install manually, or click Download from Releases.
  • Windows and Linux: Click Restart Now to apply the update immediately, or click Download manually.
